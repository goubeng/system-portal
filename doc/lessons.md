# Lessons

- 用户要求 Docker 由人工启动：门户只显示当前启动状态，去掉启动按钮及前端启动动作，帮助和提示不得再引导点击启动 Docker。

- 用户指定综合门户固定端口为 8484，不占用 3000；服务监听、启动/停止脚本、开发代理及页面/文档默认地址必须一致修改。

- 用户明确 Docker 提示用途是防止忘记打开 Docker Desktop：主提示应基于桌面进程显示“已启动/未启动”，引擎健康另列为诊断信息，不能把引擎检测超时等同于软件未打开，也不应仅因引擎探测超时拦截项目启动。

- 用户反馈帮助中按 4010 排查未能定位启动失败：排障必须先区分门户入口、业务 Web/API 与端口槽位；查询某端口无监听仅表示该端口空闲，不能认定整个项目正常或未运行。帮助中的地址与命令应与当前配置一致。

- 多项目端口编号必须基于完整项目注册表持久分配，不能根据当前抽样项目临时重排。
- 同一业务的原生版和 Vue 版应作为两个实现条目展示，并在说明中标明替代关系；不能因为业务名称相同就让两个进程共享端口。
- 本机进程门户不得提供任意命令输入框；所有可执行文件、参数、工作目录和端口必须来自受控配置。
- Windows PowerShell 5.1 会误读无 BOM UTF-8 脚本中的中文；面向双击执行的 ps1 入口必须保持 ASCII，中文说明放 README 或由程序页面展示。
- 综合门户启动时只能启动门户自身，禁止自动启动任何业务项目；所有项目必须由用户在卡片上手动启动。
- 每个业务项目仍需保留独立启动能力，门户只是统一演示入口，不能成为项目运行的强制依赖。
- 演示模式使用后台隐藏进程，不弹出额外 PowerShell 窗口；浏览器关闭不代表服务停止，必须通过门户停止按钮或 stop-portal.ps1 结束。
