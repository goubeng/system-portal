# Findings

- 浏览器不能直接安全执行本机 PowerShell；必须通过仅监听 127.0.0.1 的本机管理服务执行预登记白名单动作。
- 原生项目可以由门户内置静态文件服务启动，无需为每个原生仓库增加 Node 依赖。
- Vue 全栈项目必须让 Web/API 端口成对选择并动态同步代理，不能只让 Vite 自行换端口。
- Docker Desktop 可以由门户启动，但数据库容器启停、建库和迁移仍应保持显式运维操作。
- Windows 端口占用判断不能只尝试监听 `0.0.0.0`；已有进程只监听 `127.0.0.1` 时可能被漏判，因此门户同时检查 TCP 连接和独占绑定。
- 健康检查不能只判断 HTML 返回 200；各静态/Vite 项目还需匹配自己的页面标识，避免把其他占用端口的页面误识别为本项目。
- 01 原生会场和 07 Vue 会场是同一业务的两套实现；门户保留两张卡片，并将 01 标记为待退役，便于演示对比和后续切换。
- 系统卡片地址列表已按访问终端分组；移除外层“访问地址”标签时，保留 PC端/移动端分组可避免地址来源不明确。
- 新版会场预定移动端使用 Vue Router 的 `/m` 根路由，与 PC端共用 3701 Web 服务，无需新增端口或启动项。
- 门户可按同名且包含 `replacement` 生命周期的项目组成版本卡片；卡片只切换前端操作目标，后端仍按项目 ID 管理独立进程，保证新旧版可分别启停。
- 版本卡片默认选新版；标题下方终端标签只保留图标，访问地址区域再显示 PC端或移动端名称，兼顾紧凑展示与地址辨识。
- 版本切换、终端图标与技术标签应作为卡片标题后的独立区块，与序号左边缘对齐，避免受系统名称长度影响。
- 版本切换使用 58px 等宽胶囊分段并居中，选中状态通过实色背景突出，避免因文字长度造成视觉偏移。
- 新增外部协作文档目录时，门户后端需显式允许 `E:\AI\协作文档` 作为受控项目根；`AI协作控制台` 的真实路径是 `E:\AI\协作文档\AI协作控制台`，当前为 Vue/Vite 应用，按 npm 项目启动。
